# 部署与恢复

## 前置条件

- 使用电视所属者授权的 ADB，屏幕出现授权提示时确认。
- 原生语音助手自身可用，原生服务处于启用状态。
- 已安装目标播放器，且播放器公开兼容搜索接口。
- Python 3.10+；ADB 可自行安装，也可由 `--download-adb` 从 Google 官方站点下载。

`--check` 是默认操作。它读取设备属性、应用接口和启用状态，并短暂建立本机 ADB 转发探测原生 DDS；最后移除该转发。不会安装 APK、开启无障碍或更改电视设置。

## 部署事务

1. 校验设备档案、原生 URI 与总线，以及目标搜索接收器。
2. 校验 APK 的 SHA256；从源码构建的自定义 APK 可用 `--sha256` 显式指定。
3. 在本地原子保存修改前状态。
4. 安装新增插件。若已装公开版，当前版本拒绝自动覆盖，防止签名冲突和丢失既有配置。
5. 用受 DUMP 权限保护的配置广播写入目标包、组件和时序。
6. 追加无障碍服务，不覆盖原有列表。
7. 保留原生助手界面，配置本机语音 URI 的默认处理程序。
8. 检查默认处理程序是否真正生效。

默认入口优先通过已有 ADB shell 的 package-manager 管理权限设置；若固件不支持对应接口，则回退到电视系统的“打开方式”选择界面。插件仅在部署窗口期间尝试选择自身，不会在日常使用中自动点击其他系统对话框。

## 回滚记录

`backups/<时间与随机后缀>/state.json` 包含设备识别信息、原无障碍列表、应用启用状态、浮窗 app-op、原 URI 处理程序和操作日志。备份保存在电脑，不能当作公开 issue 附件。

恢复只接受同一 serial 和型号，防止把另一台电视的服务列表写过来。新装的插件保留为停用，不卸载原有应用。恢复后原 URI 入口按记录重设；若 OEM 拒绝管理接口，脚本会报告未完成的步骤，不能把部分恢复说成成功。

原输入法、桌面、USB 模式、ADB 开关和 ADB 密钥从未修改，因此不需要“恢复”这些设置。

## 从个人适配版迁移

检测到 `com.local.voiceinput/.VoiceInputService` 时，需要显式 `--replace-legacy`。脚本将其状态写入备份，在新插件配置完成后停用旧插件，避免同时接收同一次语音结果。失败恢复旧服务列表和旧应用状态。

## 恢复后重新使用公开版

恢复会停用新增的公开版而保留其 APK 和私有配置。v1.0 不自动覆盖已经存在的公开版，因此不能再次双击部署脚本来强行覆盖。确认还是同一已验证 APK、配置未变化后，可重新启用包、在系统中启用其无障碍服务，并把原生 URI 入口重新选为 TV语音桥。修改目标配置或升级版本前，应先保存原配置，使用相同签名的构建，不要用卸载绕过签名冲突。

这个限制是当前版本明确的升级边界，后续可增加带配置导出与 APK 备份的升级事务。

## 最后的真实遥控器验收

脚本安装成功只表示安装和接口检查通过。还要测试：

1. 输入框内说片名，文字填入且页面不退出。
2. 桌面说“我想看某片名”，约 5 秒后目标应用出现正确搜索词。
3. 一个非影片指令仍由原生助手响应。

不能用 `adb input keyevent` 替代真实遥控器对专用麦克风链路的验证。
