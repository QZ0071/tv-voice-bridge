# 新增设备适配

目前应用端只实现 Rocky / DDS 协议；JSON 档案只能描述这个适配器的设备差异，不能凭一份 JSON 把小爱、Google Assistant 等不同语音栈变成 DDS。

## 新增 Rocky / DDS 设备

需要逐项确认：

- 精确型号、板型和 SDK 范围；不能只根据品牌匹配。
- 麦克风按下 / 松开的广播是否与适配器相同。
- 本机消息总线的地址、握手与识别结果字段。
- 原生影片语义 URI、事件名、影片 title 的位置与原处理程序。
- 真实遥控器麦克风能否由原生服务正常取音。
- 输入框回填和 task affinity 是否正常。
- 目标播放器的搜索入口。

`dangbei-dds-candidate` 仅是明确同意后的实验入口，不会自动套用 K1 Pro 的音频 workaround。验证通过后提交精确 match 的设备档案、脱敏验证记录与必要的应用端适配代码。

## 新增其他语音栈

新增 Java 原生语音事件适配器与部署探测器。优先使用厂商公开的本地接口或 Android 标准 RecognitionService；不要提取、发布服务凭据，不要绕过 DRM，也不要把停止原生语音服务误当成获得遥控器麦克风访问权。

新适配器至少应包含：输入会话识别、结果接收、影片语义解析、原请求转回、兼容性拒绝路径和回滚测试。未知设备应保留未适配状态，不能靠降低 SDK、root 或修改系统分区来强行宣称通用。
